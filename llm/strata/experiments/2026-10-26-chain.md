# 2026-10-26 — checkpoint chain (prefix growth) on L40

The cold matrix measured 1k/100k/200k/262k as **separate conversations**, so
every cell re-prefilled from zero. The warm run proved checkpoint reuse for
byte-identical prompts. This run measures the case an agent actually has:
**one growing conversation**, where each turn extends the previous prompt and
the engine should prefill only the delta.

One probe invocation per pack, one fixed salt, one conversation slot, one
sequential request per stop:

```
turn 1  prompt ~1,024    -> generate 512  (cold prefill)
turn 2  prompt ~100,000  -> generate 512  (expect reuse of turn 1)
turn 3  prompt ~200,000  -> generate 512  (expect reuse of turn 2)
turn 4  prompt ~262,144  -> generate 512  (expect reuse of turn 3)
turn 4 repeat            -> 512           (cheap exact-prompt cache check)
```

Prompts are prefix extensions by construction: one salt line, then
`record000000: ...` filler appended in order (`llm/bench/probe.py --mode
chain`). The chain runner is `llm/strata/chain-cache.sh`; it reuses the exact
cold/warm launch recipe and verifies the engine start line.

## What the numbers say

- **Checkpoint reuse does engage, at 16,384-token granularity.** Turn 2
  (100k) reused **0**: the only prior checkpoint was turn 1's ~1k prompt,
  below one checkpoint block. Turns 3 and 4 reused **98,304 = 6 × 16,384** and
  **196,608 = 12 × 16,384**. The engine log is explicit: the 99,855-token
  prompt created `6 checkpoints`, and the next turn reused exactly those 6
  blocks; the 199,675-token prompt added 6 more, and the 262k turn reused 12.
  The engine's `conversation_cache.last_tokens` shows the checkpointed length
  including the generated tail (1,538 / 100,366 / 200,186), while the next
  prompt only shares the prompt part — hence the ~1.5-3k token remainder that
  is re-prefilled.
- **The exact repeat proves the ceiling.** A byte-identical prompt at 261,055
  tokens reused **261,050 = prompt − 5** (the chat-template tail), TTFT
  **0.415 s**, matching the 64k warm-cache observation (`reused = prompt − 5`).
  So the checkpoint path is intact at the model ceiling; the 98,304/196,608
  values on growth turns are block granularity, not a cache failure.
- **TTFT is driven by the delta, not the full context.** Turn 4 prefilled
  64,447 tokens in 17.7 s at 261k context; the cold 262k cell needed 63.8 s.
  Turn 3 prefilled 101,371 tokens in 25.9 s; the cold 204.8k cell needed
  48.6 s. Decode rate is flat across the ladder (116-129 tok/s strict, 7.7-8.7
  ms TPOT) — prefill is the only thing the checkpoint changes.
- **The 8 GiB / 4-slot budget was not exceeded, but it did evict.** Parked
  conversations grew 3 → 4 and stayed there; `bytes` peaked at 6.78 GB
  (IQ3_S) / 6.80 GB (Coder); evictions accumulated 0,0,1,2,6 as each new
  longer checkpoint aged out an older one. The latest checkpoint (the one the
  next turn needs) always survived. `restores` stayed 0: reuse came from the
  prompt-checkpoint path, not a parked-slot restore.
- **Coder behaves like IQ3_S** on prefill/reuse (98,304 and 196,608 at the
  same stops, 0.414 s exact repeat), with ~5-8% lower strict decode and an
  early EOS (182 tokens) at the top context after 512 was requested.

## Caveats

- This is **not a multi-turn chat transcript**: the "conversation" is one user
  message whose text grows. No assistant turn is inserted between prompts, and
  the next prompt does not include the previous generated tokens. That is the
  cleanest way to isolate prefix-growth prefill; a real agent loop that appends
  an assistant message and a new user turn has a slightly different prefix
  boundary.
- The top stop is clamped: nominal 262,144, measured prompts 261,055 (IQ3_S)
  and 261,954 (Coder) because the chain reserves 512 completion tokens and 128
  safety tokens. The model ceiling is still exercised within ~1.1k tokens.
- Cold comparison is directional only: the stored cold cells generated 128
  tokens; the chain generated 512 (Coder stopped at 182 on the top turns).
  TTFT and prefill are comparable; aggregate is not.
- One sample per turn (plus one exact repeat at the top). No variance estimate,
  no concurrency. The chain is C1 by definition.
- The job exit code is 2 solely because the runner was edited mid-run; see the
  provenance caveat. Re-running is expected to reproduce the turn table but
  would pay the ~20-25 min staging read again.
- The 4x V100 chain (`strata-chain-v100-4x`) is defined but **pending / not
  run**; volta05 was still owned by the V100 campaign.

  --tokens-per-turn 512 --chain-last-repeats 1 --budget-min 60 \
  --outdir $WORK_ROOT/strata-runs/2026-10-26-chain

`llm/strata/chain-cache.sh --self-test` proves the prefix-growth contract with
the stub server (no GPU/Slurm): prefix extensions, growing `reused`, shorter
delta prefill, strict decode/TPOT, and one CSV row per turn.
