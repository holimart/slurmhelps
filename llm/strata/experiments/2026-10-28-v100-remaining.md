## R2 — NVLink/P2P transport

Hardware (`nvidia-smi topo -m` / `nvlink -s`): all four GPUs are **NV2** (NVLink 2.0),
6 links × 25.781 GB/s per GPU; topology is all-to-all NVLink, not PCIe.

Microbenchmark (`cudaMemcpyPeer`, 256 MiB × 20):

| path | GB/s |
|---|---:|
| local HBM d2d | 407.97 |
| peer GPU0→GPU1 (same NUMA) | **48.50** |
| peer GPU0→GPU2 (cross NUMA) | **48.50** |
| `cudaMemcpyAsync(Default)` 0→1 | 48.50 |
| device→host | 13.15 |
| host→device | 12.41 |
| GPU→host→GPU staged | 12.76 |

**The engine does not use it.** During a layer-split cell the NVLink throughput
counters (`nvidia-smi nvlink -gt`) moved **0.000 MiB** on every GPU, while the
engine's own probe reports **12.4 GB/s host→device (PCIe)** and sets
`pcie_frac = 0.34`. So the layer handoff is on the host/PCIe path: the measured
peer path is **3.8× faster than staged PCIe** (48.5 vs 12.76 GB/s) and the hardware
has ~155 GB/s per GPU available. This is a concrete software target: making the
layer split use peer copies (or a peer-capable transport) could remove the
interconnect component of the 4-card prefill penalty.
