# 2026-10-23 — OpenCode agent tasks on Qwen3.5-122B-A10B (2× A100)

The 122B checkpoint was served through the slurmhelps controller and tested
with the real OpenCode CLI, not just an HTTP client.

## Serving

```bash
slurmhelps-serve --config llm/qwen35/config-122b.json up --yes \
  --backend-command bash /work/ffa/holecem/slurmhelps-fleet/llm/qwen35/serve-122b.sh
```

- vLLM 0.32, compressed-tensors 4-bit WNA16/Marlin, TP2, BF16 KV.
- `max_model_len=262144`, `max_num_seqs=32`, `max_num_batched_tokens=8192`.
- `--disable-custom-all-reduce` is required; without it TP2 workers spin in
  NCCL at 100% CPU and never load weights.
- `--enable-auto-tool-choice --tool-call-parser qwen3_coder` lets OpenCode use
  read/grep/glob/edit/shell tools.
- Load time: **~26 min** from Lustre.
- KV: **2,561,861 tokens**, 9.77× at 262K.

OpenCode provider:

```json
"slurmhelps-qwen": {
  "npm": "@ai-sdk/openai-compatible",
  "options": {"baseURL": "http://ampere02:8002/v1", "apiKey": "dummy"},
  "models": {"qwen35-122b-a10b": {"name": "Qwen3.5-122B-A10B (A100)"}}

```

## Local OpenCode benchmark

`llm/qwen35/opencode_tasks.py` creates a disposable git repo and asks OpenCode
to do four tasks:

1. **repo_search** — grep the repo, report `calc.py:<line>` in `ANSWER.txt`;
2. **tool_use_fix** — run unittest, find/fix the `add` bug, rerun tests;
3. **coding** — implement `parse_ranges`, run tests;
4. **multi_step** — search, fix, run tests, report command/result.

Run:

```bash
python3 llm/qwen35/opencode_tasks.py \
  --model slurmhelps-qwen/qwen35-122b-a10b \
  --timeout 600 \
  --output llm/qwen35/experiments/data/2026-10-23-opencode-qwen35-122b.json
```

Result: **4/4 passed**.

| Task | Result | Time |
|---|---|---:|
| repo_search | PASS (`calc.py:5`) | 19.0 s |
| tool_use_fix | PASS (4 unittest tests OK) | 29.5 s |
| coding | PASS (4 unittest tests OK) | 37.0 s |
| multi_step | PASS (4 unittest tests OK) | 39.7 s |

The model used `grep`, `read`, `edit`, `write`, `glob` and `shell` tools
correctly, and ran `python3 -m unittest discover -s tests` itself.

A first attempt failed because the temporary repo had no `.git` and OpenCode
searched the parent checkout instead. The benchmark now runs `git init` in the
fixture and sets `PWD`, which fixed the path isolation.

## Public benchmarks worth running locally

| Benchmark | Measures | Local cost |
|---|---|---|
| **BFCL** (`ShishirPatil/gorilla`) | function/tool calls, AST correctness | low–medium |
| **RepoBench / RepoBench-P** | repository retrieval + code completion | low |
| **SWE-bench Lite/Verified** | real repo issue repair with tests | high (Docker images) |
| **Aider Polyglot** | multi-language code editing | medium |
| **Terminal-Bench** | shell/tool-use agents | medium–high |
| **τ-bench** | multi-turn tool use | medium |
| **BigCodeBench / LiveCodeBench** | executable code generation | medium |

Recommended order for this hardware: **local OpenCode suite → BFCL → RepoBench
→ SWE-bench Lite**. SWE-bench is the expensive one; each instance needs a
repository snapshot and test environment.

## Caveat

The Qwen3.5 checkpoints declare **262,144 native context**. These tests do not
establish 700K behaviour. The GLM REAP50 768K path remains the 700K option; a
Qwen long-context extension or DeepSeek V4 Flash on larger hardware is a
separate experiment.
